Privacy policy

Hermes Gmail · last updated 1 November 2026

Who operates it

Hermes Gmail is operated by Yao-Ting Huang for personal use. It runs on the owner's own computer as part of a local Hermes assistant and acts only on the owner's own Gmail account. It is not a public or multi-user service.

Google permissions

  • gmail.readonly: used now, to read mail as described below.
  • gmail.send (optional, planned): requested for owner-approved sending and replies. This capability is not yet enabled. If it is configured, it will need separate Google consent, and every message will need the owner's approval of the exact recipients and content. The permission alone never authorizes the integration to send mail by itself.

Hermes Gmail does not request gmail.modify or gmail.compose. It does not delete mail, change labels, archive messages or change read status. It does not create Gmail drafts. It does not request Calendar or Drive permissions.

Data accessed

  • Headers, message and thread bodies, and attachment metadata (for example file name, type and size) of new email.
  • Short excerpts from a limited number of recent sent messages, used to match the owner's writing style.
  • Selected older threads, read-only, only when the owner separately asks for calibration. Ordinary monitoring considers new email only.

How data is used

The data is used only to identify tasks that are relevant to the owner, to propose replies, and to send selected summaries of important mail and proposed reply text to the owner. Explicit feedback and preference rules from the owner, including example messages that the owner selects, are used to improve this triage for the owner.

Hermes Gmail does not sell Google user data, does not use it for advertising, and does not use it to train generalized AI models.

Storage

The integration runs locally. On the owner's computer it stores:

  • OAuth credentials, in files that only the owner can read;
  • minimal triage records about processed messages;
  • proposed reply drafts (stored locally, not in Gmail);
  • preference rules that the owner provides.

Sharing and transfer

Email data is not kept only within Google and the owner's computer. It is transmitted to these services:

  • AI provider: selected message content and sent-message style excerpts go to the AI provider that the owner configured in Hermes, for inference.
  • Telegram: selected summaries and proposed reply text are delivered to the owner through Telegram.

These providers handle the data they receive under their own terms, policies and the owner's account settings. Hermes Gmail makes no claim about their retention, logging or model-training practices. No Google user data is shared with any other party.

This documentation site is static. It does not access Gmail and does not receive OAuth tokens or mail content from the integration.

Retention

Local records, proposed drafts and preference rules stay on the owner's computer until the owner deletes them. There is no automatic deletion schedule. Copies sent to the AI provider or Telegram are kept according to those services and the owner's settings there.

Owner controls

  • Revoke Google access at any time at myaccount.google.com/permissions.
  • Disable local polling in Hermes to stop mail monitoring.
  • Delete the local integration records, drafts, rules and credential files.
  • Manage or delete copies on the AI provider and Telegram with the controls that those services provide.

Revoking Google access does not automatically delete local records or messages already delivered to Telegram.

Google API Services User Data Policy

Hermes Gmail's use and transfer of information received from Google APIs will adhere to the Google API Services User Data Policy, including the Limited Use requirements. This is a commitment by the operator, not a certification or a verified compliance status.
